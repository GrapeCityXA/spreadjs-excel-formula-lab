# Methodology and Judgement Rules

## 1. Pipeline

```
cases/public/*.json
   ├─ SpreadJS runner (Node + local Chrome/Edge)
   │    loads @grapecity-software/spread-sheets through a real <script src>
   │    per case: write inputs → write formula → read value / displayText / inputs / readRange
   │
   ├─ Excel runner (Windows + PowerShell + Excel COM, optional)
   │    one sheet per case (sheet name = case ID) → write inputs → write formula → read Value2 / Text
   │    saves oracle/excel-oracle-workbook.xlsx as an auditable record
   │
   └─ compare.mjs
        validates engine self-check, case file SHA-256, case count, and input snapshots on both sides
        → per-case verdict: PASS / FAIL / INVALID / EXEC_FAIL / INCONCLUSIVE
        → structured classification for FAIL (environment / product / undetermined)
```

`npm run check` uses the Excel baseline already committed to the repository, so it only needs Node + a browser; only `npm run refresh` invokes the local Excel to regenerate the baseline.

## 2. Judgement Rules

| Dimension | Rule |
| --- | --- |
| Numeric | Absolute or relative tolerance of `1e-9`; matching either one counts as agreement. A case can widen this explicitly with `tolerance` |
| Text / boolean / error code | Exact comparison (case-sensitive) |
| Date | Normalised to an Excel 1900 date-system serial value, including the 1900 leap-year compensation |
| Multi-cell results | Compared cell by cell via `readRange`; the row and column counts must match as well |
| Volatile functions | Marked `volatile`, currently judged `INCONCLUSIVE` and not counted as a pass |
| Dynamic arrays | By default the declared range is read as a CSE array formula; with `arrayMode: native` the actual spill range is compared |
| Input fidelity | Both sides save a snapshot of the inputs after writing; a mismatch with the case declaration yields `EXEC_FAIL` |

## 3. Reproducibility Constraints

- Every run records the engine version, the case file SHA-256, the self-check result (`=1+1` must be 2), and a timestamp.
- Before comparing, validate that the number of results on both sides matches the case count and that the input snapshots on both sides agree; abort immediately otherwise.
- The Excel baseline is committed under `oracle/` and contains `manifest.json` (Excel version / build / locale / date system) together with an openable `excel-oracle-workbook.xlsx` for inspection.
- Run artifacts (`out/`) are not committed; what is committed are the result snapshots under `oracle/` and `site/`.

## 4. Difference Classification (automated hint)

| Classification | Common cause |
| --- | --- |
| `EXCEL_FUNCTION_UNAVAILABLE` | Add-in not installed in Excel, or the Excel version lacks the function |
| `EXCEL_ERROR_ONLY` | Excel errors while SpreadJS is fine (may also be a function-support difference) |
| `LOCALE_DIFF` | Currency symbol, regional format, DBCS settings |
| `SPREADJS_ERROR` | SpreadJS returns an error while Excel is fine |
| `ERROR_CODE_DIFF` | Both sides error but the error codes differ |
| `TYPE_DIFF` | Result types differ (number/date/text/bool/error) |
| `VALUE_DIFF` | Values differ with a relative error > 1e-6 |
| `PRECISION_DIFF` | Value difference on a relative scale of 1e-9 to 1e-6 |
| `TEXT_DIFF` / `BOOLEAN_DIFF` | Text / boolean results differ |
| `ARRAY_VALUE_DIFF` | Some cells in the range differ |
| `ARRAY_SHAPE_DIFF` | The actual spill range of a dynamic array differs |

The classification is only a hint and cannot replace a case-by-case review. When a difference appears, check the case, the Excel version/add-ins, the SpreadJS configuration (`ExcelCompatibleCalcMode`, culture) and the raw inputs.

## 5. Known Limitations

1. **Excel version**: The baseline represents only the Excel on the machine that ran `npm run refresh`. Different versions/languages/add-ins produce different results, so a report must carry the environment fingerprint.
2. **Arrays**: The default CSE mode cannot demonstrate native spill behaviour; `arrayMode: native` also does not yet cover blocked spills, empty results, or range changes after recalculation.
3. **Volatile functions**: TODAY / NOW / RAND and similar are currently only type-checked, with no numeric assertion.
4. **Locale**: SpreadJS defaults to `zh-CN` to align with this baseline; the Excel side records the current PowerShell locale and does not guarantee coverage of every Excel locale/format option.
5. **Empty strings and error inputs**: On the Excel side, empty strings are simulated with the formula `=""` and error inputs are generated by formula, which is not equivalent to typing a constant by hand.
6. **Single-sheet scope**: Cases only use A1:AZ200 of a single worksheet and contain no cross-sheet references, defined names, or structured table references.
7. **Performance**: Recorded for reference only, not used as a conclusion.

## 6. Configuration Dimensions

The same corpus is always run against two SpreadJS configurations; the report presents them in separate columns and never merges the statistics:

- `default`: SpreadJS default calculation behaviour.
- `compatible`: `GC.Spread.CalcEngine.ExcelCompatibleCalcMode = true`.

When the same case has inconsistent PASS/FAIL across the two modes, the result is configuration-sensitive; show both configurations separately in the report.
